## (a) What the reconstructed logic DOES vs the `d5e6a58` base

### `cross_m_relative_mtf.py` (src) — three new pure, unit-tested helpers
1. **`focus_peak_at_edge(seqs, vals, edge_frac=0.06)`** — focus-coverage flag.
   Returns True if the best-focus frame (`argmax` of the per-frame sharpness)
   sits within 6 % of either END of the scanned stack, i.e. the sweep did not
   bracket the true peak. Returns False for <5 frames (unknown = not flagged).
2. **`coverage_ok(edge_flags)`** — per-config verdict from per-patch edge flags.
   Majority rule: incomplete (returns False) when `sum(flags) > len/2`. Empty
   → True (unknown = keep). A few edge-field patches are tolerated (field
   curvature); a majority means the whole sweep missed focus.
3. **`p2_rail_available(rail_ok)`** — the **tier gate** for the P2 through-focus
   corroborator. P2 measures focus-stack response WIDTH in FRAMES, comparable
   only when the rail step is constant + registered. Parses the CSV
   `p2_rail_ok` column (truthy strings `1/true/yes/y/t`; `None`/empty → True for
   backward-compat with the original 38-config subset that lacks the column).

### `cross_m_relative_mtf_run.py` (driver)
- **`--subset` / `--out` CLI args + `_resolve_paths()`** (module globals
  `SUBSET_PATH` / `OUT_PATH`, wired into `extract`, `padedge`, `analyse`).
  Omitting them reproduces the original 38-config run verbatim; the expanded
  run points at a SEPARATE subset + output dir so the 38-config outputs are
  never overwritten. Every `OUT/…` path in extract/analyse/padedge switched to
  `OUT_PATH`, and `SUBSET` → `SUBSET_PATH`.
- **Multi-session sid uniqueness + dedup/supersession.** `sid()` now suffixes a
  compact `@YYMMDD` session tag onto every NON-baseline session (the
  `2026-01-29` validated baseline keeps its canonical sids so the §L reference
  groups + order-regression check are unchanged). Prevents collisions where
  the same `(lens, mag, aperture)` recurs across sessions
  (e.g. `S105_1_1_F8` in both 2026-01-29 and 2025-10-17). `human()` appends the
  date for non-baseline sessions too. Extra abbreviations added
  (`extension→ext`, `RaynoxM-→R`, `EVO→` dropped).
- **Tier-aware P2 degradation.** Per config the driver computes
  `p2_rail_ok = X.p2_rail_available(c["p2_rail_ok"])`. psffoc (the P2
  through-focus FWHM rows) are emitted **only when `p2_rail_ok`** is true —
  the whole MANUAL tier (2025-10-17 / 2026-01-29 / 2026-02-18: hand start/stop,
  fixed step COUNT → non-constant, unregistered step) degrades to the
  spectral / pad-edge / decon estimators. Meta now carries `date`,
  `p2_rail_ok`, `coverage_ok`, `n_edge_patches`, `n_focus_patches`.
- **Focus-coverage flagging (all tiers, bites the manual tier).** During
  extract it runs `focus_peak_at_edge` over each patch's curve, sets
  `coverage_ok` on the meta row, and prints `COVERAGE INCOMPLETE: k/n …` when a
  config fails. In `analyse` an **incomplete-coverage DROP** removes those sids
  from meta + psd before ranking and prints them (backward-compatible: a meta
  without the column keeps every config — applies to ALL estimators, not just P2).
- **Rail-coverage-tier-only ranking view.** When ≥3 `p2_rail_ok` configs exist,
  analyse prints a SEPARATE ranking + gate over just the rail-coverage tier
  (the most-trustworthy, constant-registered-rail data) alongside the full set.
- **Self-describing outputs.** The ranking CSV is merged with
  `date / p2_rail_ok / coverage_ok / n_edge_patches / n_focus_patches`
  (`write_ranking_csv` gained an optional `table=` arg). A new
  `session_summary.csv` reports per session: tier (rail-coverage vs manual),
  `n_ranked`, best/worst rank.

### `test_cross_m_relative_mtf.py`
New tests for all three helpers — `p2_rail_available` (default-true / truthy /
falsey / bool passthrough + a "P2-unavailable configs absent from scores"
integration test), `focus_peak_at_edge` (edge-peak / centered / too-few-frames),
and `coverage_ok` (majority rule + tie behaviour).
